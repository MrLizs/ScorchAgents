# sainit-dating — 交友类项目初始化

## 目标

根据用户描述，产出一个能点、能跳、能看到主要社交玩法的 HTML 原型——比如滑动匹配、消息列表、聊天窗口、个人主页，让用户先看到产品长什么样。

同族的卡还有 `sainit-shop` / `sainit-blog` / `sainit-tool` / `sainit-saas` / `sainit-other`，分别对应不同行业；这张带社交类的常见玩法底子。

## 输入

- 必需：项目描述。
- 可选：用户点名的功能、风格偏好、目标用户。

## 产出

- `prototype/index.html`（进入/登录）及若干功能页面（文件名自定）。
- `prototype/assets/`：样式和交互脚本。
- `README.md`：项目说明 + 页面清单 + 怎么预览。
- `STEPS.md`：写入项目元信息（见"交接"）。

## 硬性底线

- 每个按钮和链接点了必须有反应——跳到已存在页面、弹提示、或切换状态，不要死链。
- 每条数据要能看到"增 → 查 → 改 → 删"的回路，哪怕用 localStorage 模拟。
- `STEPS.md` 必须写"项目元信息"节，至少包含：项目名（中英文）、项目类型（dating）、功能清单、页面清单、Tab 配置。字段是下游卡的共同输入，名字不要改。

## 交接

- 写完 `STEPS.md` 后，下游通常是 `safrontend`；也可能先做视觉迭代再进前端。
- `safrontend` / `saapi` / `sabackend` / `saapi-connect` 都从 `STEPS.md` 读元信息。

## 自由发挥

- **UI 风格**：不设固定 5 选 1。自己按调性定，或问用户想要什么感觉。
- **功能取舍**：滑动匹配、即时聊天、附近的人、动态广场、实名认证、会员、兴趣社群等等，从描述推导或和用户商量，不必套预设清单。
- **页面划分、Tab、导航**：自己定。
- **技术细节、占位图、要不要问用户**：全部自行判断，不套固定话术。
