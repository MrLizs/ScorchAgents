# sabackend — 接口落地为后端

## 目标

照着 `api/openapi.yaml` 把每个接口实现出来：建库建表、写路由和处理逻辑、加认证和校验，最后产出能直接建库的 SQL 文件。做完后核对一遍，确保规范里的接口一个不落。

## 输入

- 必需：`api/openapi.yaml`（由 `saapi` 产出）。
- 可选：`api/API.md`、`api/mock-data.json`、`STEPS.md`（项目名、技术栈偏好、后台模块清单）。

## 产出

- `backend/`：可运行的后端服务（按你选的技术栈组织目录）。
- `backend/sql/init.sql`：建表 + 初始数据 + 运行参数默认值。
- `STEPS.md`：追加"后端开发"节，记录技术栈、接口实现清单、审核结果。

## 硬性底线

- **配置分段**：数据库连接信息（host/port/账号/密码/库名/Redis）放在框架的配置文件里（`.env`、`config.yaml`、`application.yml` 等，按框架惯例来）；业务运行参数（JWT secret、过期时间、第三方 key、上传域名、限流阈值等）默认值写进 `init.sql` 的 `system_config` 表。
- **代码不许硬编码运行参数**：JWT secret、第三方 key 这类值不能写死在代码里，也不能从环境变量/yaml 直接读，统一从一个封装（如 `ConfigService`）读 `system_config` 表，带个短时缓存。
- **启动要自检数据库**：服务启动时对每个用到的数据库连一次，往控制台打印连接成功/失败的明确信息；失败就抛错退出，不要静默跳过。
- **避开数据库保留字**：字段名不要用 `order`、`group`、`user`、`key`、`status`、`type` 这类保留字，加业务前缀或换个名字。SQL、ORM 模型、DTO 都要遵守。
- **SQL 可重复执行**：`init.sql` 重复跑不会插出重复数据。
- **接口全覆盖**：生成完对照 `openapi.yaml` 逐个核对，每个接口都要有实现和记录。
- **不动 `api/` 目录**：那是 `saapi` 的地盘，只读不改。

## 交接

- 下游是 `saapi-connect`（接通前端和后端）和 `saadmin`（按 Admin 接口生成后台）。
- `STEPS.md` 里记下技术栈、项目中文名、接口清单，`saapi-connect` 和 `sadeploy` 都要读。

## 自由发挥

- **语言、框架、架构、数据库选型**：自己判断或和用户商量，原卡里的固定选项表已删除。
- **目录结构、分层方式、ORM、测试策略、缓存策略**：自己定。
- **业务逻辑细节、校验规则、错误处理**：按接口语义和项目需要来。
- **`STEPS.md` 的具体写法**：字段语义在即可，格式随意。
