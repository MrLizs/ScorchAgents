# safrontend — 原型转前端代码

## 目标

把 `prototype/` 里的静态页面变成一套能跑的前端项目：有框架、有路由、有状态管理、有 API 客户端占位，页面能交互、能跳转。产出的代码要和原型在视觉上基本一致。

## 输入

- 必需：`prototype/` 目录（由某张 `sainit-*` 产出）。
- 可选：`STEPS.md`（项目名、风格、页面清单等，读到就用，读不到就自己问或从原型推导）。

## 产出

- `frontend/`：前端工程（框架、构建配置、页面组件、路由、状态管理、API 客户端）。
- `frontend/README.md`：怎么装依赖、怎么启动、目录结构。
- `STEPS.md`：追加"前端开发"节，记录技术栈和运行方式。

## 硬性底线

- 页面清单以 `prototype/` 里实际存在的页面为准，不要凭空加页面。
- 保留一套 API 客户端的抽象层（例如 `src/api/client.ts` + 按模块拆的文件），让后面的 `saapi-connect` 能直接填 baseURL 和认证——它不会重写你的文件结构。
- `STEPS.md` 里记下选了什么框架、是否用 TypeScript、UI 库、状态管理方案；`saapi-connect` 要读这些来适配。

## 交接

- 下游是 `saapi`（从前端代码反推接口），再往后是 `sabackend`。
- `saapi-connect` 依赖这里留下的 API 客户端抽象层和 `STEPS.md` 的框架记录。

## 自由发挥

- **框架、语言、UI 库、状态管理、构建工具**：全部自己判断或和用户商量，原卡里的固定选项表已删除。
- **渲染方式**（SPA / SSR / SSG）、**PWA**、**图标方案**、**响应式断点**：按项目需要决定，没有默认答案。
- **代码组织**：目录怎么分、组件怎么拆、样式用 CSS Modules 还是 Tailwind 还是别的，自己定。
- **要不要分阶段让用户确认**：自行判断，不套固定流程。
