# sanative-bridge — 原生能力桥接

## 目标

给端侧工程加一层平台无关的原生能力接口：业务代码用同一套调用方式，底层按平台自动切换实现。只做用户真正需要的那些能力，不做全家桶。

## 输入

- 必需：`mobile/` 或 `desktop/`（端侧工程）。
- 可选：用户点名的能力清单。

## 产出

- `mobile/src/native/` 或 `desktop/src/native/`：按需生成的桥接模块 + 统一导出 + 平台检测工具。
- 平台权限声明（如 iOS Info.plist、AndroidManifest.xml）按需补齐。
- `STEPS.md`：追加"原生桥接"节。

## 硬性底线

- **每个模块都要有 Web / 不可用环境的降级实现**——能力拿不到时友好报错或走替代方案，不要直接崩。
- 接口风格统一（例如 async 函数 + options 参数对象），别每个能力一套写法。
- 权限声明随模块自动生成，别让使用者手动补。

## 交接

- 上游是 `sacrossplatform` / `sadesktop`，下游是端侧业务代码调用这些模块。

## 自由发挥

- **做哪些能力**（相机、相册、定位、推送、文件、生物识别、分享、地图、通知、托盘等）：按需求选，原卡清单只是举例。
- **每个能力的 API 设计、权限文案、降级策略**：自己定。
- **模块文件怎么拆**：按能力或按平台都可以，只要统一导出即可。
