# sainit — 项目类型识别与分流

## 目标

从用户的一句话描述里判断项目类型，推荐一张初始化任务卡（sainit-dating / sainit-shop / sainit-blog / sainit-tool / sainit-saas / sainit-other），让用户拿着这张卡直接开工。

这一份**只做判断和指路**，不生成原型、不建目录、不问 UI 风格。

## 输入

- 必需：用户对项目的一句话描述。
- 可选：用户已经明确说出的类型、角色、目标平台。

## 产出

- 一句类型判断 + 一张推荐的任务卡名字 + 一句理由。
- 不写文件。

## 硬性底线

- 判断不出类型时，选 `sainit-other`，不要瞎猜一个具体类型。
- 同时命中多种类型（例如"社交电商"），选 `sainit-other`，由通用卡承接。
- 多角色项目（例如 SaaS 有公众端、控制台、后台）在推荐里提一句"建议按角色拆工程"，具体的拆法交给对应的初始化卡处理。

## 交接

下游是某一张 `sainit-*` 初始化卡。把用户描述原样传过去即可，本卡不写 `STEPS.md`。

## 自由发挥

- 类型怎么判断、要不要向用户确认、用哪种措辞推荐，全部自行决定。
- 用户描述里出现新类型（不在现有六类里），可以直接建议新建一张卡，不必硬塞进现有分类。
