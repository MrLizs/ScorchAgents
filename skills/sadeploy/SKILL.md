# sadeploy — Web 全栈部署

## 目标

根据项目实际用的技术栈和部署环境，生成一套能跑的部署脚本：拉代码、装依赖、初始化数据库、配反向代理、启服务、配 SSL，同时给出更新和回滚的做法。

## 输入

- 必需：`STEPS.md`（技术栈、端口、数据库）、`backend/`、`frontend/`。
- 可选：`admin/`、用户指定的服务器系统和部署方式。

## 产出

- `deploy/`：部署脚本（按目标系统命名）、Nginx 配置、容器编排文件（如用容器）、部署说明。
- `STEPS.md`：追加"部署"节，记录目标环境和脚本清单。

## 硬性底线

- 脚本要覆盖全栈所有部件，别只部署前端或只部署后端。
- 密钥、密码、域名等环境相关值不要写死，用变量或环境变量占位。
- 数据库初始化脚本要可重复执行，不破坏已有数据。
- 给出回滚路径——更新失败时能退回上一个版本。

## 交接

- 这是 Web 链路的终点；移动端走 `sadeploy-mobile`，桌面端走 `sadeploy-desktop`。

## 自由发挥

- **目标系统、原生部署还是容器部署、用不用面板**（宝塔 / 1Panel 等）：按用户环境定，原卡固定清单已删除。
- **Nginx 配置、SSL 方式、进程管理、目录布局**：自己决定。
- **脚本语言和组织方式**：按系统选（.sh / .ps1 等）。
