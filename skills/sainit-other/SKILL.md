# sainit-other — 通用项目初始化

## 目标

根据用户描述，产出一个能点、能看、页面之间能互相跳转的 HTML 原型，让用户先看到"这东西长什么样、有哪些页面"，再决定要不要写真正的前端代码。

同类卡还有 `sainit-dating` / `sainit-shop` / `sainit-blog` / `sainit-tool` / `sainit-saas`——那些是带行业模板的版本；这张是兜底，**不预设页面和功能**。

## 输入

- 必需：项目描述。
- 可选：用户已经说清的页面、功能、角色、风格偏好。

## 产出

- `prototype/index.html` 及若干功能页面（文件名自定）。
- `prototype/assets/css/`、`prototype/assets/js/`：样式和交互脚本，按你采用的方案组织。
- `README.md`：项目一句话说明 + 页面清单 + 怎么预览。
- `STEPS.md`：写入项目元信息（见"交接"）。

## 硬性底线

- 每个页面里出现的按钮和链接，点了必须有反应——跳到已存在的页面、弹提示、或切换状态，三选一；不要留死链。
- 每条数据要能看到"增 → 查 → 改 → 删"的完整回路，哪怕用 localStorage 模拟。
- `STEPS.md` 必须写"项目元信息"节，至少包含：项目名（中英文）、项目类型（other 或实际类型）、功能清单、页面清单、Tab 配置（如有）。这几个字段是下游卡的共同输入，名字不要改。
- 多角色项目建议拆成 `prototype-web/`、`prototype-console/`、`prototype-admin/` 等，`STEPS.md` 里记一笔"工程清单"和"目录映射"；下游卡按这个映射找文件。

## 交接

- 写完 `STEPS.md` 后，下游通常是 `safrontend`（原型转前端代码）；也可能先做视觉迭代再进前端。
- `safrontend` / `saapi` / `sabackend` / `saapi-connect` 都从 `STEPS.md` 读项目元信息，字段名保持一致即可。

## 自由发挥

- **UI 风格**：不设固定选项。自己根据项目调性定，或者问用户想要什么感觉。
- **功能清单**：从描述里自行推导，不必套任何预设列表；拿不准的可以问。
- **页面划分**：几个页面、怎么导航、几个 Tab，自己定。
- **技术细节**：纯 HTML/CSS/JS 还是引一点库、样式怎么组织、占位图用什么服务，全部自己决定。
- **要不要问用户、问几个问题**：自行判断，不要套固定话术。
