# saapi-connect — 前后端接通

## 目标

把 `safrontend` 和 `saadmin` 里的假接口、假登录、假数据，换成调用 `sabackend` 的真实 API：配好地址、注入登录凭证、统一处理错误、解决开发环境跨域。

## 输入

- 必需：`frontend/` 和/或 `admin/`（前端代码）、`backend/`（后端服务）、`api/openapi.yaml`。
- 可选：`STEPS.md`（框架、技术栈、工程清单）。

## 产出

- 修改 `frontend/` 和 `admin/`：环境变量、API 客户端、认证逻辑、页面里的数据调用、错误处理。
- 修改 `backend/`：CORS 配置。
- `STEPS.md`：追加"前后端接通"节，记录改了哪些文件、验证结果。

## 硬性底线

- **只填空，不重写**：沿用前端已有的 API 客户端抽象层和目录结构，不要推倒重建。
- **登录流程要完整**：登录拿 access + refresh → 请求时自动带上 → 401 时刷新 → 刷新失败跳登录。
- **清干净假数据**：所有写死的 token、假用户、内联的假数组都要换成真实接口调用；清理要显式做，因为前端可能被重新生成过。
- **统一错误处理**：HTTP 错误和业务错误都要给提示，401/403 单独处理。
- **不动 `api/` 目录**，也不处理 HTTPS 证书和线上反向代理（那属于部署阶段）。
- **每做完一步就记一笔 `STEPS.md`**，不要等全部做完再补记。

## 交接

- 下游是部署类任务卡：`sadeploy`（Web）、`sacrossplatform` / `sadesktop`（端），或 `saapi-platform`（平台化扩展）。

## 自由发挥

- **环境变量怎么命名、proxy 怎么配、CORS 白名单放哪些地址**：按实际项目定。
- **错误提示的文案、loading 状态、401 跳转细节**：自己决定。
- **验证方式**（手动点、脚本跑、端到端测试）：自己选，能确认接通即可。
- **多工程项目的配对**：按 `STEPS.md` 里"工程清单/目录映射"逐个接通，后端合并的就只接一次。
