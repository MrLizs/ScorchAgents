# sainit-blog — 博客类项目初始化

## 目标

根据用户描述，产出一个能点、能跳的 HTML 原型——文章列表、详情、发布编辑、收藏、分类等，让用户先看到内容浏览和创作的主流程。

同族的卡还有 `sainit-dating` / `sainit-shop` / `sainit-tool` / `sainit-saas` / `sainit-other`，分别对应不同行业；这张带内容类产品的常见页面底子。

## 输入

- 必需：项目描述。
- 可选：用户点名的栏目、功能、风格偏好。

## 产出

- `prototype/index.html` 及若干功能页面（文件名自定）。
- `prototype/assets/`：样式和交互脚本。
- `README.md`：项目说明 + 页面清单 + 怎么预览。
- `STEPS.md`：写入项目元信息（见"交接"）。

## 硬性底线

- 每个按钮和链接点了必须有反应——跳页面、弹提示、或切换状态，不要死链。
- 内容主流程要能走通：列表 → 详情 → 发布/编辑 → 收藏/删除，哪怕用 localStorage 模拟。
- `STEPS.md` 必须写"项目元信息"节，至少包含：项目名（中英文）、项目类型（blog）、功能清单、页面清单、Tab 配置。字段是下游卡的共同输入，名字不要改。

## 交接

- 写完 `STEPS.md` 后，下游通常是 `safrontend`；也可能先做视觉迭代再进前端。
- `safrontend` / `saapi` / `sabackend` / `saapi-connect` 都从 `STEPS.md` 读元信息。

## 自由发挥

- **UI 风格**：不设固定 5 选 1。自己按内容调性定，或问用户。
- **功能取舍**：文章、分类、标签、搜索、发布、评论、收藏、订阅、专栏等等，从描述推导或商量，不必套预设清单。
- **页面划分、Tab、导航**：自己定。
- **技术细节、占位图、要不要问用户**：全部自行判断，不套固定话术。
